Answer
Python's Global Interpreter Lock (GIL) is a mutex that allows only one thread to execute Python bytecode at a time[1]. This means CPU-bound multithreaded programs see little speedup, because threads cannot run Python code in true parallel[2]. I/O-bound workloads still benefit, since the GIL is released during blocking I/O operations, letting other threads run[1]. For CPU-bound parallelism, the standard recommendation is to use the multiprocessing module, which sidesteps the GIL by running separate processes[3].
